# Brand assets (`assets/brand/`, `scripts/gen_logo.py`)

The logo is an 8-bit starburst on an ink tile, **generated** — `scripts/gen_logo.py` holds character grids (one letter per pixel) plus a six-entry `PALETTE`, and emits every SVG/PNG/ICO/terminal-banner from them, so the 16px favicon and the 1024px export can't drift. **Never hand-edit anything in `assets/brand/` except its `README.md`** — edit the sprite or the palette and re-run `python3 scripts/gen_logo.py` (Pillow is needed only for the raster exports). The generator is deterministic, so an unchanged sprite rewrites byte-identical files and a noisy diff means the art really changed. The 16px cut is a **separate sprite**, not a downscale — at that size the bevel and cast shadow turn to mud, so it's two colours and 2px arms.

The palette is not a second brand: all six values are tokens the docs site already ships (`--color-brand-300/400/600/800` plus slate-800/900 in `lesysbot.github.io/src/styles/main.css`), so adopting the mark was a change of shape only. Change a brand token there and the table in `assets/brand/README.md` is what has to follow.

The site's copies under `lesysbot.github.io/src/assets/` (`favicon.svg`, `favicon.ico`, `logo.svg`, `wordmark.svg`, `apple-touch-icon.png`, `og-image.png`) are **copies** — regenerating here does not update them; the copy commands are in `assets/brand/README.md`. The mark is referenced as an `<img>` via `brandMark()` in `src/lib/layout.js`, never inlined (~1500 `<rect>`s × 69 pages × 2 placements). Assets sit outside the `lesysbot/` package dir on purpose so hatchling never bundles them into the wheel.

**In the terminal, the mark reaches two kinds of consumer and they get it differently.** The Python CLI can't read `assets/` at all (outside the package → absent from the wheel and from a PyInstaller build), so `gen_logo.py` also writes the 16px grid + palette into **`lesysbot/core/_logo.py`** — generated, data only, ~600 bytes; same trick as `webui/page.py` inlining its HTML. **`lesysbot/core/banner.py`** (hand-written) renders that through Rich, which downgrades truecolor for 256/16-colour terminals on its own; `_print_status` puts it beside the version. The **install/uninstall scripts** instead `cat` `assets/brand/banner{,-small}.txt`, because they run before Python is known to exist. Both paths gate on TTY + `NO_COLOR` + `TERM != dumb` and no-op when the file/console can't take it. Shell must use `sed`, not `printf` — the files are raw escape codes and `printf` would read them as a format string. Half-blocks pack two pixel rows per line, and a transparent top **must** use `▄` with a foreground, never a space with a background (that fills the whole cell and squares off the tile's cut corners). `tests/test_banner.py` decodes the render back to the sprite and fails if `_logo.py` drifts from the generator.
