# Setup wizard (`lesysbot/setup/`) and install scripts (`scripts/install.{sh,ps1}`)

The install scripts are **bootstrap only**: check Python ≥3.11, `pip install ".[all]"` (so Telegram and Discord both work), locate the `lesysbot` binary, then hand off to **`lesysbot setup --repo <checkout>`** (bash `exec`s it; ps1 forwards `$LASTEXITCODE`; `-NoService` skips the hand-off). The wizard itself is **one cross-platform Python implementation** in `lesysbot/setup/`, shared by every OS, and `--repo` is development-only — a normal install seeds from the content bundled in the wheel (`paths.bundled_dir()`). `lesysbot setup` also runs standalone at any time to reconfigure an existing install. It writes `config.yaml` and seeds `tools/`, `dashboards/`, `catalog.json` and the `dashboard/` stack into **`~/.lesysbot/`** (`user_dir()`, overridable via `LESYSBOT_HOME`) and points the service's `WorkingDirectory` there; `tools_dir`/log paths stay relative in the written config and anchor to `~/.lesysbot` at load time. Seeding goes through the artifact installer's rules and records packages as `bundled: true`, so a fix to a bundled package reaches people who already have it. The Grafana dashboard is **default, not optional**: after config it always runs `apply.start_dashboard` (see `dashboard/CLAUDE.md`). `scripts/uninstall.{sh,ps1}` offer to stop whichever stack is present (brew services and/or containers) and to remove `~/.lesysbot`.

Module layout — `ui.py`: Rich-panel widgets (`InteractiveUI.menu/text/confirm_yn`) rendered in a transient `Live` that leaves a one-line `❯ label · answer` echo behind; `read_key()` reads **raw bytes from the stdin fd via `os.read` inside a `raw_mode()` (cbreak) context held for the whole widget** — per-keypress termios toggling loses queued bytes to the canonical line buffer (fast typing/paste kept only the first char), and `sys.stdin` readahead hides bytes from `select()`, desyncing escape parsing. Escape sequences are collected byte-by-byte with a 0.25 s timeout and whole CSI sequences are slurped so Home/Del/F-keys can't leak. `text(..., secret=True)` masks the typed chars/default-hint/echo with `*` (password entry — the Grafana password uses it; `PlainUI` reads it via `getpass`). `PlainUI` is the no-terminal fallback (numbered "type a number" menus via `input()`, EOF → default + `eof` flag); `make_ui()` picks by `isatty`. `wizard.py`: `WizardState` dataclass + the step chain (`step_llm`/`step_messaging`/`step_autostart` + `run_steps`, `show_summary`/`step_summary`), `ask_allowed_ids()` shared by the Telegram and Discord branches, and the Ollama picker. `apply.py`: config template, package seeding (`seed_tools`/`seed_dashboards`/`seed_catalog`), the Grafana stack (`seed_dashboard`/`start_dashboard`, gated by `_docker_running` on Linux and `_brew_ready` on macOS), per-OS service setup (Windows via PowerShell `ScheduledTask` cmdlets), and `read_config_state()`; the service and stack functions take a `runner` param so tests record instead of touching the host. `cli.py`: argparse wiring + the top-level flow (seed → service → `start_dashboard` → epilogue); dispatched in `__main__.main()` before the artifact CLI.

- **Navigation contract**: ↑/↓ move, Enter/→ confirm, number keys jump; when a menu has a "← …" entry, ←/Esc confirms it directly (inert otherwise); Esc at a text prompt returns `None` and the step loops re-show that step's menu with answers intact. The summary is a menu (Apply / Change LLM backend / Change how to reach LeSysBot / Change startup behaviour (service only) / Quit); nothing is written until Apply. Revisited steps offer previous answers as defaults — except LLM follow-ups, cleared when the backend choice changes. The kept-config path (existing config not overwritten) has no chain — just y/N service + apply questions; its summary is filled by `apply.read_config_state()`, which parses the existing `config.yaml` back into a `WizardState` (missing keys fall back to the `LLMConfig` model defaults the bot would actually run on), so it shows the install being kept instead of a blank state.
- **Messaging step is framed as "How to reach LeSysBot"**: option 1 is the terminal (default → `provider: cli`); Telegram/Discord are additive remote channels. A **background service (systemd/launchd/Task Scheduler) is installed for every provider** (`WizardState.needs_service` is always True) — it serves the always-on control panel, and additionally runs the bot when a remote provider is configured; with `cli` it serves the panel and idles. Both remote providers require a non-empty allow-list — `ask_allowed_ids()` re-asks until valid, and in `PlainUI` mode aborts (`SetupAborted`) when piped input runs dry (`ui.eof`). The wizard ends with a provider-aware "How to use" epilogue that names `lesysbot setup` for reconfiguring.
- **The service path stops-and-replaces + `restart`s** so a changed config actually takes effect. There is no stale-service cleanup any more: every setup installs the service, so there is never a leftover one to remove (uninstall is `scripts/uninstall.{sh,ps1}`). `apply.setup_service` takes a `runner` like the per-OS functions, so tests never touch the host's systemd/launchd/Task Scheduler.
- **No sudo, ever** — and this holds project-wide, not just for the wizard. "Enter through the prompts" must stay password-free, and **no tool may require root either**: never shell out through `sudo`, never ship a sudoers script, prefer the unprivileged source of the same fact, and where none exists say so in the reply instead of elevating (`docs/writing-tools.md`, "Never require root"). The bundled `power` package stays because `shutdown` goes through logind/polkit for a local session.

Tests: `tests/test_setup_wizard.py` drives the chain through a scripted `FakeUI` (navigation, defaults preservation, backend-switch clearing, Telegram/Discord validation and EOF, summary jumps, `read_config_state` round-trips), plus config/package seeding, dashboard start (Linux auto-start-vs-manual menu, Linux Docker-not-ready fixes, the macOS brew flow — auto-install, manual choice, Docker mentioned when running, and the no-Homebrew fallback — Windows native-Grafana instructions, `LESYSBOT_SKIP_DASHBOARD`, no-dir no-op; `_ran_script` matches on the script argument rather than the whole command line, because a `tmp_path` readily contains the word 'start'), the Grafana credential prompt + `grafana.env`/`dashboard/.env` persistence, and service functions via a recording runner (the `setup_cli.run` tests stub `apply.setup_service` outright, so a test run can never install a real systemd/launchd/Task Scheduler service; hermetic through `LESYSBOT_HOME`/`HOME` monkeypatching; `shutil.which`/`sys.platform` monkeypatched for the docker/OS probes, `FakeUI.messages` records printed instructions). `test_config.py` also covers `parse_env_file`/`load_grafana_env` (file→env, explicit env wins). Every prompt is documented in `docs/getting-started.md`. Naming note: `lesysbot/setup/` is the *install wizard*; `lesysbot/artifacts/` is the *package installer* — unrelated modules.
